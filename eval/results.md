# Benchmark results

> **Run mode: deterministic-only.** Stage 1 is the whole pipeline here. The router, Tavily and the explanation stage are not exercised, so *checks with zero model calls* is trivially 100% and *cost per check* is trivially $0. Neither number means anything until the run goes through the router. Read them as placeholders, not results.

Generated by `uv run python -m eval.runner`. Every case carries the registry metadata it needs, so the run is offline and a rerun gives the same numbers.

- Clocks: each case is judged against its own `verified_at`. 0 of 150 carry one; the rest fall back to `2026-10-26T12:00:00+00:00`. Range `2026-10-26T12:00:00+00:00` .. `2026-10-26T12:00:00+00:00`. Re-verifying one case never moves another.
- Ecosystems covered: docker, pypi.
- Cases: **150** | passed: **150**

## Rule attribution

Which policy rule actually fired, per case class. This is what separates a working check from a lucky one: a malicious package that was already pulled from the registry is caught by P1 (`not_found`) and says nothing about whether P2 (`osv_malicious`) works at all.

The deciding rule is the strictest one that matched — the one the verdict rests on. Several rules match a single case, so the second column shows coverage and the first shows what actually decided.

| Class | Deciding rule | Every rule that fired |
| --- | --- | --- |
| benign | `P9` ×50 | `P9` ×50 |
| malicious | `P2` ×46, `P2+P4` ×4 | `P2` ×50, `P6` ×50, `P4` ×4, `P5` ×4 |
| hallucinated | `P1` ×30 | `P1` ×30 |
